# ESO analizatorius

Пишет историю счётчиков отключений электроэнергии со страницы
[eso.lt/atjungimai-planiniai-neplaniniai](https://www.eso.lt/atjungimai-planiniai-neplaniniai)
и показывает её графиками.

**Дашборд: https://maji9ibahbl4.github.io/EsoAnalizator/**

ESO публикует только текущее состояние — истории на сайте нет. Здесь снимок
берётся каждые 15 минут, складывается в CSV прямо в репозитории, а дашборд на
GitHub Pages читает эти CSV из браузера. Ни сервера, ни базы, ни ключей.

```
collector/collect.py          сборщик (только стандартная библиотека Python)
tools/demo_data.py            генератор демо-истории для проверки вида графиков
collector/run_local.ps1       один цикл: снимок → коммит → push
collector/run_hidden.vbs      запуск без мелькающего окна консоли
collector/install-task.ps1    регистрация задачи в планировщике Windows
.github/workflows/collect.yml прогон в Actions — вручную, расписание выключено
docs/index.html               дашборд (GitHub Pages)
docs/app.js  docs/style.css   графики, без сборки и без зависимостей
docs/data/YYYY-MM.csv         история, по файлу на месяц (UTC)
docs/data/index.json          список месяцев — дашборд читает его первым
docs/data/latest.json         последний снимок
```

## Источник данных

Страница ESO — это AngularJS-приложение; счётчики приходят отдельным JSON:

```
GET https://www.eso.lt/atjungimai-planiniai-neplaniniai/statdata

{"success":true,"data":{"k":{"total":3382},"c":{"total":1289},
                        "n":{"total":31405},"p":{"total":0}},
 "timestamp":1787902517}
```

| поле | на сайте | смысл |
|---|---|---|
| `k` | Klientų pranešimų skaičius | сообщения клиентов |
| `c` | Sutrikimų skaičius | сбои |
| `n` | Dėl sutrikimų atjungtų klientų skaičius | отключённые из-за сбоев |
| `p` | Dėl planinių darbų atjungtų klientų skaičius | отключённые из-за плановых работ |

Первые 11 замеров (24–28 августа) сняты вручную, до запуска сбора, и
внесены из таблицы через `tools/import_manual.py`. Плановых отключений в
той таблице не было — не потому, что их не измеряли, а потому, что все
эти дни там стоял ноль и записывать его не было смысла. Ноль проставлен
задним числом по свидетельству того, кто снимал замеры.

Два важных свойства, которые определили формат хранения:

* Это **моментальные** значения (сколько активно сейчас), а не накопительный
  итог: счётчики и растут, и падают по мере устранения сбоев.
* Поле `timestamp` — серверная метка кэша, **не** признак свежести данных: она
  не менялась четыре минуты подряд, пока сами счётчики двигались. Поэтому
  временем замера считается `ts_utc`, который пишет сборщик, а `timestamp`
  хранится просто для справки.

## Где работает сбор

Не в облаке. `eso.lt` стоит за Cloudflare, и на IP дата-центров он отвечает
JS-челленджем «Just a moment…» (HTTP 403) — и на JSON-эндпоинт, и на саму
страницу; проверено на runner'ах GitHub Actions. С домашнего соединения тот же
запрос обслуживается нормально, поэтому сборщик работает на домашней машине,
а GitHub хранит данные и отдаёт дашборд.

Расписание в `.github/workflows/collect.yml` поэтому закомментировано, а ручной
запуск (`workflow_dispatch`) оставлен: им удобно проверить, не изменилось ли
поведение. Если появится хост, которому сайт отвечает, — расписание
включается расскомментированием двух строк.

Плата за это — **дыры в истории, пока машина выключена или спит**. Задача
поставлена с флагом «запустить при первой возможности», так что после
пробуждения пропущенный цикл выполняется сразу, но время сна не восстановить.
Если дома есть что-то всегда включённое (Raspberry Pi, NAS), сбор стоит
перенести туда: `collect.py` — чистый Python без зависимостей, нужен только
cron и `git push`.

## Установка на этой машине

```powershell
powershell -ExecutionPolicy Bypass -File collector\install-task.ps1
```

Регистрирует задачу планировщика «ESO analizatorius - collect»: каждые
5 минут `run_hidden.vbs` → `run_local.ps1` → снимок. Окно консоли не
появляется. Лог — `collector/run.log` (в git не попадает).

Сбор и публикация идут на разных часах: снимок берётся каждые 5 минут, а
коммит с push — примерно раз в 15, по три снимка за раз. Причина в лимите
GitHub Pages: 10 сборок в час, а каждый push запускает сборку. Так
разрешение данных втрое выше, а пушей остаётся 4 в час.

```powershell
Start-ScheduledTask -TaskName 'ESO analizatorius - collect'   # прогнать сейчас
Get-ScheduledTaskInfo -TaskName 'ESO analizatorius - collect' # когда был/будет
powershell -ExecutionPolicy Bypass -File collector\install-task.ps1 -Uninstall
```

Задача выполняется от вашего пользователя и только когда вы вошли в систему —
иначе `git push` не получит доступ к сохранённым учётным данным Git.

Частота меняется параметром: `install-task.ps1 -IntervalMinutes 10`.

**Настоящий такт источника — 5 минут, а не 15.** На странице ESO написано
«atnaujinama kas 15 min.», но замер показал другое: серверная метка
`timestamp` сдвигается ровно каждые ~300 секунд, и вместе с ней
пересчитывается `n`. Опрашивать чаще смысла нет — новых чисел по главному
показателю не появится.

Отдельная деталь: счётчики живут на разных часах. `c` (число аварий)
меняется непрерывно, раз в 30–60 секунд, независимо от кэша; `n`
(отключённые клиенты) стоит между пятиминутными обновлениями и прыгает
только вместе с меткой.

## Вручную

```bash
python collector/collect.py              # один снимок в docs/data/
python collector/collect.py --dry-run    # показать, ничего не записывая
python -m http.server -d docs 8000       # дашборд на http://localhost:8000
```

Флаги: `--data-dir` (или переменная `ESO_DATA_DIR`) — куда писать; `--lenient` —
предупредить и выйти с кодом 0 вместо падения, если ESO не ответил. По
умолчанию сборщик падает: зелёный прогон, который ничего не собрал, хуже
красного — дыру в истории замечаешь спустя месяцы.

`run_local.ps1 -NoPush` — полный цикл без отправки в GitHub.

## Демо-данные для проверки вида

Настоящая история растёт по 96 строк в сутки, поэтому увидеть, как графики
ведут себя на длинном периоде, можно не раньше чем через месяцы. Скрипт
подделывает такую историю — шторма разной силы поверх суточного ритма, тем же
15-минутным шагом:

```bash
python tools/demo_data.py            # 92 дня в .demo/
python tools/demo_data.py --serve    # и сразу открыть на http://127.0.0.1:8000
python tools/demo_data.py --days 365 # год истории
```

Результат кладётся в `.demo/` (в git не попадает). `docs/data/` скрипт не
трогает: сгенерированные числа не должны оказаться в настоящем ряду.

## Вежливость к источнику

Проверено, а не предположено:

* `robots.txt` на eso.lt закрывает `/apps/`, `/config/`, `/vendor/`,
  `/modules/` и `.pdf` — наш путь не закрыт. Там же указан
  `Crawl-delay: 10`; обычный прогон делает **один** запрос раз в 15 минут,
  что с большим запасом внутри этого правила. Запасной путь с прогревом
  страницы выдерживает эти 10 секунд явно.
* Сборщик представляется собой и даёт ссылку на репозиторий, а не
  прикидывается Chrome. Эндпоинт отвечает одинаково в обоих случаях, так
  что маскировка ничего не давала, а возможность оператору сайта нас
  опознать или связаться — даёт.
* Нагрузка: 96 запросов в сутки по ~130 байт ответа. Страница целиком
  (40 КБ) больше не грузится на каждом прогоне — только если прямой
  запрос отказал.
* Собираются публичные агрегированные счётчики. Персональных данных нет,
  авторизация не обходится, ничего не парсится из закрытых разделов.
  Источник указан на дашборде и здесь.

## Что стоит знать про эксплуатацию

* **Публикация отложена относительно сбора.** Свежий снимок попадает на
  дашборд не мгновенно, а с задержкой до 15 минут — он ждёт своей пачки.
  Локально в CSV он уже есть.
* **Повторный запуск подряд не оставит пустой строки.** Если значения те
  же, что в последнем замере, и прошло меньше пяти минут, сборщик ничего
  не пишет: источник обновляется раз в 15 минут, и такой замер — тот же
  самый. Два одинаковых замера с нормальным интервалом сохраняются оба:
  это два измерения, которые совпали, и то, что значение держалось, —
  тоже факт.
* **Push не прошёл — не беда.** Следующий запуск делает `git pull --rebase` и
  отправляет оба снимка. Поэтому обрыв сети не теряет данные.
* **Объём.** 96 строк в сутки, ~60 байт на строку — около 2 МБ в год плюс
  история коммитов. Файлы разбиты по месяцам, дашборд грузит только нужные.
* **Репозиторий публичный** — этого требует GitHub Pages на бесплатном плане.
  Собранные данные и история коммитов видны всем.

## Дашборд

* Периоды: 24 часа / 7 дней / 30 дней / всё. Выбор попадает в адрес
  (`#range=168`), так что ссылкой можно поделиться.
* Плитки с текущими значениями, изменением за период и спарклайном.
* Два графика: отключённые клиенты (сбои и план) и записи (сообщения и сбои).
  Разные величины — разные графики: две шкалы на одном поле рисуют связь,
  которой в данных нет.
* Наведение (и стрелки ← → с клавиатуры) — перекрестье со значениями всех
  серий на этот момент; кнопка «Показать таблицу» даёт те же числа текстом.
* Тёмная и светлая темы; палитра проверена на различимость при дальтонизме.
* Время показывается в `Europe/Vilnius`, хранится в UTC.
